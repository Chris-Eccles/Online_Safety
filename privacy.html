In short

The Abity sites keep almost nothing about anyone. There are no accounts, no logins for students or staff, no adverts, no tracking and no analytics.

  • Students' names are never stored. A student types their name when they hand in work. It goes to their teacher in one email and is then forgotten by the site.
  • What is kept is a mark, the time of hand-in, and a scrambled code that stops the same student handing in twice. None of these can be turned back into a name.
  • The AI marker never sees a name. It only sees the question, the mark scheme and the answer.
  • Staff using the CPD site type nothing that is sent anywhere. Their course notes stay on their own device.

This notice explains each of these points in plain English, and the glossary at the end explains every technical term.

What happens to a name at hand-in

The name travels one way only: into the teacher's email. The AI marker and the site's storage never receive it.

The "hashed name" explained

The phrase "the name is hashed and stored" sounds as if the name is kept somewhere. It isn't. What is stored is a code that cannot be turned back into a name.

What actually happens

  1. The site takes the name the student typed, for example Sam Patel, together with the homework it is for.
  2. It mixes these with a secret key that only the site knows, using a standard method called HMAC-SHA-256 (the same family of methods banks use to check transactions).
  3. The result is a string of 32 random-looking characters, such as 9f2c71e0a4b85d3e….
  4. Only that code is kept. The name itself is thrown away.

Next time someone hands in the same homework, the site makes a code from their name in the same way. If the codes match, it knows that student has already handed in. That is the only thing the code is used for.

A useful comparison: a hash is like a fingerprint of the name. If you're given a fingerprint, you can check whether it matches a person standing in front of you, but you can't work out from the fingerprint alone who it belongs to.

Common worries, answered

Worry What really happens
"The name is in a database anyone can look at." The name is never written to any database. Only the 32-character code is.
"A hacker could read the names." There are no names to read. Someone who stole the codes would have a list of meaningless strings. Because each code also uses a secret key and the homework it belongs to, they couldn't even guess names and check them.
"It can be decoded." Hashing is one-way by design: there is no method to reverse it. It is not encryption, which is two-way.
"The same code follows a student around." No. The code for Sam on Homework 1 is completely different from the code for Sam on Homework 2, so codes can't be linked to build up a record of one student.
"Marks are stored against names." Marks are stored only against the code, so the site itself has no way to say whose mark is whose. Only the teacher's email links a name to a mark.

Lawful basis and the GDPR principles

Lawful basis. Setting, marking and giving feedback on schoolwork is part of the school's job of educating students. Under UK GDPR this is public task (Article 6(1)(e)), the same basis the school uses for its other teaching records. No special category data (health, religion, ethnicity and similar) is asked for or kept.

UK GDPR has seven principles. This is how the sites meet each one.

Principle What it means How the sites meet it
Lawfulness, fairness and transparency Have a good reason, be fair, and tell people Public task basis; this notice is linked from every page
Purpose limitation Use data only for the reason you collected it Names are used only to tell the teacher whose work it is
Data minimisation Collect no more than you need No accounts, no class lists, no email addresses; just a typed name at hand-in
Accuracy Keep data correct Students type their own name; teachers can clear a hand-in so it can be redone
Storage limitation Don't keep data longer than needed Names aren't stored at all; marks go when the teacher deletes the work, and automatically every August; IP addresses go after 15 minutes
Integrity and confidentiality Keep data secure Passwords, encrypted connections, rate limits and one-way codes (see Security)
Accountability Be able to show you follow the rules This notice, the school's records, and code that can be inspected on request

This is privacy by design: the sites were built so that the least possible data exists in the first place, rather than collecting it and then protecting it.

Security

  • Encrypted connections. Every page is served over HTTPS (the padlock in the address bar), so nothing typed can be read in transit.
  • Passwords. Each site has a front-page password, and each homework, lab and resource has its own. The admin area has a separate admin password known only to the teacher.
  • Guessing is blocked. After repeated wrong passwords from one connection, further attempts are refused for 15 minutes.
  • Emails stay in school. The site will only send hand-in emails to school mailboxes ending @mgs.kent.sch.uk. It refuses any other address, even if one is typed in by mistake.
  • Nothing worth stealing. Because names and answers are never stored, a break-in would find only marks and meaningless codes.
  • Uploaded pages are sandboxed. Interactive labs run in a locked-down "sandbox", so they can't reach the site's passwords or any other page.
  • No third-party tracking. No analytics, advertising or social media code runs on CS Online, and its fonts are stored on the site itself.
  • AI is told to ignore tricks. The AI marker is instructed to treat answers as data, so a student can't instruct it to change their mark.

Your rights and how to contact us

You have the right to see the information held about you, to have it corrected or deleted, and to object to how it's used.

In practice, the site holds nothing it can link to a named person. The hand-in emails sit in the teacher's school mailbox, where the school can find them in the usual way. A teacher can also clear a student's hand-in on the site if asked.

To use any of these rights, or with any question or worry, speak to your Computer Science teacher or contact the school's data protection officer through the school office.

If you're unhappy with how your information has been handled, you can contact the Information Commissioner's Office (ICO) at ico.org.uk.

The question box at the top of this page

The box at the top lets you ask a question about this notice in your own words. Your question and the text of this notice are sent to Cloudflare's AI service (the same one that marks homework), which writes an answer using only this notice.

  • Your question isn't stored. The site doesn't save or log it, and it isn't linked to you. Only the number of questions from each connection is counted for a few minutes, to stop misuse.
  • Please don't type names or other personal details into the box.
  • The answer is a guide, not the notice itself. If the answer and the notice ever disagree, the notice is right. For anything it can't answer, speak to the school's data protection officer.

More about CS Online

Assistive tools. If a student switches on Assistive tools in the ♿ menu (for dictation or text-to-speech), pasting and copying are allowed. The teacher's email says it was switched on and how many times text was pasted, but not what was pasted.

Progress files. Save progress file downloads a file with the student's name and answers so far, to wherever they save it (for example their school OneDrive). Load progress file opens it on another computer. The file is never sent to the site or stored on a server. Delete it when it's no longer needed.

Site password. After the front-page password is typed, the browser keeps a code showing it has been entered, so it needn't be typed again. The code isn't the password, says nothing about who the student is, and stops working when the teacher changes the password.

Coding boxes. Pressing Run or Check on a worksheet compiles and runs the code (C#, Python, VB.NET, Java or SQL) inside the student's own browser. It isn't sent anywhere until they hand in.

Worksheet feedback. When a worksheet is handed in, the AI writes a short comment on each answer. It gives no marks and never sees the name.

Lesson videos. Nothing loads from YouTube until a student presses play. Videos then play in YouTube's privacy-enhanced mode, and Google's privacy policy applies to the player. Names and answers are never shared with YouTube.

Fonts. CS Online uses Nunito, stored on the site itself (SIL Open Font License), so no font requests go to other companies, including the extra fonts in the ♿ menu.

Open-source software. The coding and SQL boxes run these open-source projects in the browser, downloaded from CS Online itself:

  • C#: WasmSharp (Apache 2.0) with Microsoft .NET and Roslyn (MIT)
  • Python: Pyodide (MPL 2.0) with CPython (PSF licence)
  • VB.NET: LiveCodes vb-wasm (MIT) with Microsoft .NET and Roslyn (MIT)
  • Java: TraceJVM 0.4.1 (GNU AGPL 3.0), using OpenJDK 23 (GPL 2.0 with Classpath Exception), TeaVM-javac (Apache 2.0) and b-jvm (MIT). TraceJVM is used unmodified; its complete corresponding source is published with that package. Licence texts: AGPL, third-party notices, corresponding source.
  • SQL: sql.js 1.14.2 (MIT, licence), a version of SQLite (public domain)

Glossary

Term Plain English
Personal data Any information that identifies a living person, such as a name
Controller The organisation that decides why and how personal data is used (here, the school)
Processor A company that handles data on the controller's behalf, only as instructed
Hash / hashing Turning text into a fixed-length code that can't be turned back. Like a fingerprint: it can be matched, not reversed
HMAC A hash that also uses a secret key, so nobody without the key can make or check codes
Encryption Scrambling data so it can be unscrambled with a key. Two-way, unlike hashing
HTTPS The secure, encrypted connection shown by the padlock in the address bar
IP address The number that identifies an internet connection, like a postal address for data. At school, all students share the school's one IP address
Database / storage Where the site keeps information between visits. Here it holds homework, marks and codes, never names
Browser storage Space inside a person's own web browser, on their own device. The site can't read it from elsewhere
Server logs Short records hosting companies keep of which pages were requested, used for running and protecting their service
Rate limit A cap on how many tries are allowed in a short time, to stop guessing
Sandbox A locked box a web page runs inside, so it can't reach anything else
AI marker A computer program that reads an answer and the mark scheme and suggests a mark and feedback
Workers AI Cloudflare's AI service, run on Cloudflare's own computers
Privacy-enhanced mode YouTube's setting that stops it setting tracking cookies until a video is played
